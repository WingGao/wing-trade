# 完善持仓看板、批次核算与分级止盈

## 目标

实现持仓市值、外部股票名称查询、日内行情图、批次浮盈与重建、等量卖出匹配和三级止盈继承，完成检查后等待提交前 review

用户已明确要求“创建任务，并直接执行，直到提交前等我 review”，本任务据此完成规划、实现与检查，停在 Git 提交之前。

## 背景

- Dashboard 已统一读取行情、持仓与收益，市值应在同一次服务端估值中产生。
- 详情没有日内曲线、浮盈和重算；`list_lots` 只计已结清批次的已实现收益，会漏掉部分卖出的收益。
- 目前仅有批次 ProfitTarget；近期已确定最近买入优先，本次在此基础上等量分配。

## 需求与验收标准

- [x] R1：Dashboard 添加“持仓总价值”，来自同次服务端估值；空仓零，缺价不可用，过期显示参考状态，不能展示部分总值。
- [x] R2：查找证券通过后端外部接口获取名称，外部结果可选中并创建本地证券；失败明确反馈且本地库仍可用，不以代码冒充名称。
- [x] R3：活动仓位股价固定三位小数，全应用股数整数展示；不改账务内部精度。
- [x] R4：详情顶部真实当日日内图每三秒刷新，初次加载完整时序；来源、时间、过期/失败状态明确。隐藏/离页暂停，无并发堆积，旧响应不覆盖新证券。
- [x] R5：批次按时间倒序，短 ID 列悬浮完整 ID；仅持有中按当前价和剩余含费成本计算浮盈金额及百分比，已结清显示破折号。
- [x] R6：重新计算有确认提示；单事务清除该账户/策略/证券派生 lots、matches 并按有效 trades 重建、修正周期。原始交易、其他证券及审计历史保留，批次止盈按 buyTradeId 恢复，重复重建稳定，失败回滚。
- [x] R7：自动卖出先按最近优先选足以覆盖的最小批次集合，再按整数股尽可能等量分配；容量不足先扣满后均分，余股按最近优先。数量守恒，差价/费用计入个股已实现盈亏，预览和确认一致。旧 FIFO、LIFO、手工匹配兼容。
- [x] R8：全局一份止盈，个股可覆盖或清空继承全局，批次可覆盖或清空继承个股/全局；继承纯展示、不存批次副本。设置按钮位于止盈目标列并显示来源，兼容旧分段目标。
- [x] R9：交易流水优先显示证券代码及名称，内部 ID 只辅助提示，时间倒序。
- [x] R10：新增/修改方法有注释，新增文档中文；本次新增及修改行 lint、后端类型/单测/集成、前端类型/构建/关键 E2E 通过。全库 Ruff 历史遗留问题见 validation.md，不宣称全库 lint 全绿。
- [x] R11：用户追加要求：开启“显示已结清”时，在个股详情同时完整展示每个已结清批次的原始买入与全部有效卖出明细，默认全部可见，无需逐行展开。显示方向、成交时间、原始成交价、本批数量、含费现金额和卖出已实现盈亏，按时间倒序。跨批次卖出只展示本批匹配数量和分摊回款，并注明原始整笔成交量，避免重复计算；关闭开关隐藏这些明细，作废交易不作为有效成交展示，账户/证券/策略严格隔离。

## 决策与边界

- “多个买入扣除相同数量”按 R7 解释，保留最近优先，避免小额卖出触及所有旧仓；重建按当前 EQUAL 策略重配有效卖出，用于纠正历史派生数据。
- 全局为应用单例，个股按 securityId 唯一；继承与浮盈均由后端 Decimal 计算。
- 不删除、不清空任何本地 ledger.db；测试和迁移验证仅用隔离临时数据库，不自动重建用户库。
- 不新增自动下单，不改手续费/精度约定，不重设计无关页面；外部源失败明确不可用，不伪造行情。
- 用户完成 review 后已明确授权提交；按 Trellis 流程保存功能提交、归档本任务并记录会话，不推送远端。
