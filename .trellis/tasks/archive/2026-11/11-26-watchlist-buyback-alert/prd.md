# 清仓关注与目标买回价提醒 — 需求规格说明书（PRD）

## 1. 目标与用户价值

部分标的在全部卖出（清仓）后，用户仍希望持续跟踪其盘中行情、对比上次卖出价，并在跌至理想目标买回价时收到推送提醒，以便把握波段回接或低位加仓机会。

当前系统仅提供全局「显示已结清 (`includeClosed`)」开关，开启后会把历史全部已结清标的混入持仓列表，噪音大、无法筛选重点跟踪标的，也不支持目标买回价与到价推送。本需求旨在打通「关注标记 + 首页开关混入展示 + 目标买回价与企微到价提醒」全链路。

## 2. 已确认的现状与约束

- **现有底层基础**：
  - 数据库已存在 `watchlist_items` 表（`backend/app/models/ledger.py:64-72`），按 `(account_id, security_id)` 唯一。
  - 后端已存在 `GET/POST/DELETE /api/v1/watchlist`（`backend/app/api/v1/router.py:527-584`），增删时已联动 `_notify_quote_hub_scope`。
  - 实时推流与缓存层（`backend/app/market_data/hub.py:232`、`backend/app/market_data/service.py:218`、`backend/app/services/dashboard.py:190-202`）已将 `WatchlistItem` 纳入订阅范围。
  - 企业微信推送渠道与异步检测引擎已存在（`backend/app/models/notification.py`、`backend/app/services/notifications/engine.py`）。
- **硬性约束**：
  - 本地 `ledger.db` 不允许删除或清空数据，数据库演进必须通过无损 Alembic 增量迁移完成（基于 `0007_security_daily_metrics`）。
  - 后端接口保持分离：`/api/v1/dashboard` 保持账务持仓职责纯净，关注列表数据由独立 `/api/v1/watchlist` 接口提供；列表混入仅作为前端展示能力。
  - 所有文档使用中文，所有新增/修改方法必须包含中文注释。

## 3. 核心需求

### R1. 关注管理（仅限已有/已交易证券）
- 支持对当前账户下的已有持仓或已清仓证券执行「关注 / 取消关注」操作，按 `(account_id, security_id)` 维度持久化。
- 支持为关注标的设置：
  - `targetBuyPrice`（目标买回价，可选，需大于 0）
  - `alertEnabled`（到价买回提醒开关，默认关闭；开启时必须填写有效 `targetBuyPrice`）
  - `note`（关注备注/买回计划，可选，最多 256 字）
- **重买保留策略**：当已关注的空仓标的重新买入变为持仓后，**保留**其关注状态及目标买回价/提醒配置；未来再次清仓时自动无缝回到关注池展示。

### R2. 前端首页开关与列表混入展示
- 在首页工具栏（桌面端与移动端）增加「显示关注」开关，**默认开启**，并将用户切换后的状态持久化到 `localStorage`。
- 后端 `/api/v1/dashboard` 与 `/api/v1/watchlist` 保持接口分离；前端独立拉取关注列表并与实时行情（`quotesStore` SSE）联动投影。
- **混入规则**：
  - 关闭「显示关注」时：首页列表仅显示原有持仓（或开启「显示已结清」时的全部历史仓位）。
  - 开启「显示关注」时：
    - 已关注的**空仓（清仓）标的**混入首页持仓列表，带有清晰的「关注 / 空仓」视觉标识；若当前价 `<= targetBuyPrice`，高亮「已到买回价」状态。
    - 已关注的**持仓中标的**不重复生成第二行，在原持仓行上叠加展示「★ 关注」标记（及目标买回价/到价提示）。
    - 同时开启「显示已结清」与「显示关注」时，按 `securityId` 去重，避免同一清仓标的重复出现。
  - 混入的空仓关注行**不得影响**账户汇总卡片（持仓总价值、浮盈、未结清持仓数等指标仍以 `dashboard.summary` 为准）。
  - 空仓关注行需展示对回接最有价值的信息：最新价与今日涨跌幅、上次卖出价与现价较上次卖出涨跌幅（`vsLastSellPct`）、目标买回价与距目标价涨跌幅（`vsTargetBuyPct`）、20日平均振幅、历史累计已实现收益。
  - 点击空仓关注行可在右侧详情面板（或独立详情页）正常查看分时图、历史已结清交易、编辑关注/买回价，以及发起买入记账。

### R3. 交互入口
- **证券详情面板（`SecurityDetailPanel.vue`）**：头部提供「★ 关注 / 已关注」快捷切换与「买回价设置」入口（弹窗配置目标买回价、提醒开关与备注）。
- **清仓卖出工作台（`SellMatchDrawer.vue`）**：当卖出预览使该标的在当前账户剩余持仓归 0 且尚未关注时，提供「清仓后继续关注」复选框（勾选后可顺手填写目标买回价与是否开启提醒），卖出记账成功后自动保存关注记录。
- **已结清列表补加**：用户开启「显示已结清」查看历史清仓股时，点进详情即可一键加关注。

### R4. 目标买回价与企业微信到价提醒
- 复用现有企业微信群机器人 Webhook 配置（`NotificationChannel`）与 `MarketDataHub` 实时行情监听机制。
- **触发规则（始终提醒）**：只要用户已启用企微通知渠道、关注项开启 `alertEnabled` 且设置了 `targetBuyPrice > 0`，在可触发行情时段内当 `last_price <= target_buy_price` 时触发推送——**无论该标的当前是否持仓（空仓回接与持仓低位加仓均触发）**。
- **幂等去重**：按 `(user_id, watchlist_item_id, target_signature, trigger_date, channel_type)` 按北京时间自然日去重；同一天同一目标价仅推送一次，修改目标买回价后若满足新条件允许重新触发。
- **消息内容**：推送中文 Markdown 卡片，包含标的名称/代码、当前价、目标买回价、较上次卖出价涨跌幅（如有）、关注备注（如有）以及估算价标识（场外基金估算场景）。

## 4. 范围之外（Out of Scope）

- 不做「搜索任意未交易新股票加入纯自选」的外部证券添加入口（聚焦已有/清仓证券）。
- 不新增除企业微信 Webhook 以外的其他外部推送渠道（如邮件、短信、飞书）。
- 不做关注列表拖拽排序 UI（保留底层 `sort_order` 字段兼容即可）。

## 5. 验收标准（Acceptance Criteria）

1. **无损迁移**：在保留现有 `ledger.db` 数据的前提下启动服务，Alembic 成功升级至 `0008`，`watchlist_items` 新增字段与 `buyback_alert_deliveries` 表创建完成，旧数据零丢失。
2. **独立关注 API**：
   - `POST /api/v1/watchlist`、`PATCH /api/v1/watchlist/{security_id}`、`DELETE /api/v1/watchlist/{security_id}` 均按当前登录用户账户隔离，参数校验准确（如开启提醒但未填有效目标买回价返回 400/422），变更后实时行情中心同步订阅。
   - `GET /api/v1/watchlist` 聚合返回关注配置、`hasOpenPosition`、`quote`、`lastSellPrice`、`vsLastSellPct`、`vsTargetBuyPct`、`realizedPnl` 与 `avgAmplitude20d`。
3. **重买保留**：对已关注的清仓标的录入买入后，关注记录、目标买回价与提醒开关完整保留；再次全部卖出后仍处于关注状态。
4. **前端混入与开关**：
   - 首页桌面端与移动端均展示「显示关注」开关，首次默认开启，刷新页面后保持用户上次选择。
   - 开启时，已关注的空仓标的混入列表展示，持仓中已关注标的叠加星标且不重复行，同时开启「显示已结清」时不出现重复行；账户汇总卡片数值不受关注行影响。
   - SSE 推送新报价时，混入的关注行实时刷新现价、涨跌幅、`vsLastSellPct`、`vsTargetBuyPct` 及「已到买回价」状态。
5. **交互闭环**：
   - 在详情面板可切换关注与保存/清除目标买回价、提醒开关与备注。
   - 在卖出配对工作台执行清仓卖出时，勾选「清仓后继续关注」并提交后，自动创建关注记录（含可选目标买回价）。
6. **企微到价提醒**：
   - 行情满足 `last_price <= target_buy_price` 且处于有效交易时段时，空仓与持仓中均能触发企微 Markdown 推送并写入 `buyback_alert_deliveries`。
   - 同一北京时间自然日内同一目标价不重复推送；修改目标买回价后若新价命中可再次推送；行情过期（`is_stale=True`）或闭市时段不误报。
7. **质量门禁**：后端 `pytest` / `ruff` / `mypy`（或项目标准检查）与前端 `type-check` / `build` / 单元测试全部通过。
