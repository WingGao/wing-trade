# 个股详情持仓汇总

## 目标

在个股详情页的持仓批次上方增加紧凑、清晰的持仓汇总，让用户无需逐批相加即可看到当前证券的总持股数、持仓成本、已实现收益和总浮盈。

## 背景与确认事实

- 现有个股详情页通过 `GET /api/v1/securities/{securityId}/lots` 加载当前账户和策略范围内的批次、累计已实现收益与行情。
- `Lot.remainingQty` 与 `Lot.remainingCost` 已由后端精确计算；`realizedPnl` 已统计同一范围内全部有效卖出配对，包括仍持有批次的部分卖出。
- 当前页面只在批次标题中显示已结清批次数和累计已实现收益，没有统一的证券级汇总区。
- 项目规范要求账务收益由后端计算，前端不得自行相加或重算盈亏。

## 需求

### R1 汇总范围与口径

- 汇总范围必须与页面当前“账户 + 证券 + 策略”的批次查询范围一致。
- 总持股数等于所有未结清、剩余数量大于零批次的 `remainingQty` 合计。
- 持仓成本等于同一批次的 `remainingCost` 合计，即含买入费用的剩余成本，不显示重量平均单价。
- 已实现收益等于该范围内所有有效卖出配对的已实现收益合计。
- 总浮盈等于同一范围 Open 批次的剩余市值减去剩余成本；没有可用行情时不得显示零或局部估值，必须显示不可用。
- 切换“显示已结清”不能被关闭批次、成交明细或异步旧响应改变汇总值。

### R2 展示与交互

- 汇总区位于持仓批次表正上方、待刷新提示之后，四项指标并列展示。
- 汇总区使用紧凑的横向指标带，不嵌套独立卡片；窄屏下可自然换行为两列。
- 总持股数按整数股展示，金额按当前证券币种展示。
- 已实现收益和总浮盈使用现有涨跌色规则；零值与缺失值保持中性。
- 缺少持仓、行情或尚未加载时使用 `—`，不得用伪造的 `0` 掩盖数据不可用。
- 总浮盈存在但行情过期时，页面必须保留现有过期行情提示，并让汇总区的参考性质可辨识。
- 移除批次标题中与新汇总重复的累计已实现收益文字，只保留已结清批次数。

## 非目标

- 不新增重量平均成本、预计卖出费用后的净浮盈、今日盈亏或收益率汇总指标。
- 不修改批次表字段、卖出配对、止盈设置、交易录入或行情采集规则。
- 不为历史已结清批次单独新增查询接口，也不改变现有已结清明细交互。

## 验收标准

- [ ] 个股详情页持仓批次表上方可见“总持股数、持仓成本、已实现收益、总浮盈”四项汇总。
- [ ] 两项未结清批次分别有剩余数量和剩余成本时，汇总值与服务端 `summary` 返回的精确合计一致。
- [ ] 部分卖出后，已实现收益仍包含该范围全部有效卖出匹配，总持股数和持仓成本只统计未结清剩余部分。
- [ ] 开启或关闭“显示已结清”时，四项汇总值保持不变。
- [ ] 行情缺失时总浮盈显示 `—`；行情有效时显示按当前价计算的未实现收益，并保持现有涨跌色。
- [ ] 切换账户或证券后，旧范围汇总不会短暂或持续覆盖新范围。
- [ ] 后端相关集成测试、前端类型检查、构建和相关 Playwright 用例通过。
