# 独立检查问题分析：无时区 UTC 成交无法编辑

## 1. 根因类别

- **跨层契约、隐含假设、测试覆盖缺口**：后端 `router.trade_data` 通过既有 `_dt` 序列化 SQLite 回读时间，可能返回不带时区的 ISO 字符串；领域服务将无时区持久时间解释为 UTC。
- 新编辑表单要求时间输入带时区，却未兼容上述真实读取格式，导致用户即使只改备注，也被不相关的时间校验阻止保存。
- 首轮前端 mock 的时间全部带 `Z`，因此类型检查和 27 项 E2E 没有暴露这个输入边界问题；独立检查对照真实服务端序列化发现了缺口。

## 2. 既有验证为何未发现

没有反复试错的修复历史。首轮回归覆盖了字段原始精度，却只覆盖理想化时间响应；`string` 类型本身不能区分无时区 UTC 与含偏移量时间。

## 3. 预防机制

| 优先级 | 机制 | 具体措施 | 状态 |
|---|---|---|---|
| P0 | 输入边界兼容 | 仅为旧无时区 UTC 原始值追加 `Z`；保留原微秒精度，不统一改写后端公共格式 | 已修复，针对回归通过 |
| P0 | 变更比较一致 | 表单预填和原值比较采用同一时间基准，只改备注不提交 executedAt | 已修复，针对回归通过 |
| P0 | 真实形态回归 | 新增无时区微秒 fixture，验证可保存备注且 PATCH 不携带未编辑时间 | `SQLite无时区UTC时间可编辑备注且不改写原始时间` 已通过 |
| P1 | 可执行规格 | 在前端持仓交互规范记录旧时间响应和 fixture 覆盖要求 | 已完成 |

## 4. 系统性排查边界

- 同类风险应在数据进入新增编辑表单时处理，不能只移除全部时间校验，亦不能凭 Date 往返重写未编辑事实。
- 本次保持既有后端接口格式和其他展示格式器不变，避免把单个编辑兼容问题扩大为全站时间展示重构。
- 跨层检查应对照实际 ORM 回读后的响应形态，不能仅以客户端类型或理想 mock 为依据。

## 6. 同轮补充：重算后读取期间切换已结清条件

### 根因类别与证据

这是异步状态契约和测试覆盖缺口。Dashboard 重算后 GET 在途时，用户仍能切换 `includeClosed`，但 `loadValuation` 因写操作进行中直接返回，未推进读取代次，导致旧开关响应可能应用到新界面。修复前回归因等不到 `includeClosed=true` 的新查询超时，已确认可复现。

### 既有验证为何未发现

原测试覆盖确认期间切范围、POST 期间切账户和旧 GET 延迟，却未覆盖重算成功后的读取窗口切换展示条件，漏掉“写范围不变但查询变化”的交叉路径。

### 预防机制与系统边界

- 已用独立 `queryGeneration` 管理读取条件，切开关使旧 GET 失效，共享重算重读等待最新稳定查询。
- 不取消同范围已在途 POST；主动替代的读取不误报为真实读取失败，不扩展到其他交互重构。
- 新增回归 `重算后的读取期间切换已结清条件，丢弃旧读取并立即按新条件重读`，修复后与 UTC 兼容回归一起通过；最终完整 29 项前端回归也已通过。

### 知识沉淀

已同步 `.trellis/spec/frontend/state-management.md` 的写后读取代次要求及持仓交互规范的错误矩阵、必须测试项。后续排查必须区分账户/证券/策略操作范围与 `includeClosed` 等展示查询，不能只用单一 mutation 布尔值忽略所有读取变化。
