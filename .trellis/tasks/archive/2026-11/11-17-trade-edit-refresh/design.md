# 交易流水编辑与待刷新：技术设计

## 状态与前提

2026-11-18 用户已确认“成交字段可编辑、账户/证券/策略/方向只读”的首版范围，并在最终规划评审后明确回复“开始实施”。本设计已获实施授权。仓库依据统一见 [调研证据](research/repository-evidence.md)。

## 职责与数据流

1. 流水表单提交原版本及变更字段，保留原始精度。
2. 编辑路由取得写事务；服务校验状态、版本和字段，复用现有 AccountingService 计算成交金额/费用。
3. 同事务更新 Trade、递增 revision、追加前后值审计，并标记对应范围待刷新；不重建派生表。
4. 首页快照与个股 lots 响应读取同一持久状态，展示提示。
5. 点击刷新，经范围确认，调用既有重算入口和 RecalculationService。
6. 重算成功后同事务清标记；异常整笔回滚。前端失效旧请求并重读服务端结果。

数据库持有状态真相，前端只显示；行情轮询不参与状态流转。保留原 API 兼容，不新建第二套重算算法。

## 持久状态

新增 `PositionRefreshState` / `position_refresh_states`：

| 字段 | 约束与用途 |
|---|---|
| id | UUID，沿用现有实体习惯 |
| account_id、security_id、strategy_id | 外键及命名唯一约束，组成唯一重算范围 |
| needs_refresh | 非空布尔，实际编辑置真，成功重算置假 |
| updated_at | UTC，记录最近状态变化 |

- 旧范围无状态行按假读取，不回填、不在 GET 建行；首次实际编辑时创建。
- 不挂在 Security 上，避免跨账户误清；不挂在 Lot/Cycle 上，避免重算删除后丢失。
- SQLite 的 `BEGIN IMMEDIATE` 串行化编辑和重算：先编辑后重算则消化该编辑；先重算后编辑则重新置真。唯一约束防止重复状态行。
- 布尔值已能覆盖当前单写入者事务，不另加任务队列或后台作业状态。刷新中是前端请求状态。

## 接口契约

### 编辑

新增 `PATCH /api/v1/trades/{tradeId}`：

- 必填 `revision` 作为编辑前版本。
- 可选 `executedAt`、`qty`、`price`、`commission`、`stampDuty`、`transferFee`、`otherFee`、`memo`、审计 `reason`。
- 非空账务字段显式传 null 为校验错误；`memo:null` 清空备注。未传字段保留，不用默认零覆盖原费用。
- 严格拒绝归属、方向、来源、幂等键、合计和派生关系等非白名单字段。
- 十进制字符串和现有规整规则不变。时间规整为 UTC 比较，未编辑的时间保留原精度。
- 返回 `{trade: TradeRead, needsRefresh: boolean}`，无实际变更返回原版本与现有状态。
- 404 用现有交易不存在错误；新增稳定 409 版本冲突/交易不可编辑错误；其他校验沿用统一 422 错误信封。所有错误均回滚。

服务方法使用现有账本层的 `TradeLedgerService.edit_trade`，路由只协调事务。审计事件使用 `TRADE_UPDATED`，记录字段前后值、版本及可选原因，更新事实更新时间；不能撤销再新增，也不能直接改派生批次伪装编辑。

### 读取

- `GET /dashboard`：positions 每行增加 `needsRefresh`；顶层增加 `pendingRefreshScopes`，包含当前快照账户下所有待刷新的证券/策略及代码名称，不依赖活动批次存在，也不受 includeClosed 影响。
- 顶层范围项显式包含 `accountId`、`securityId`、`strategyId`、`market`、`symbol`、`name`，足以绑定行操作和详情跳转。
- `GET /securities/{id}/lots`：增加当前范围 `needsRefresh` 及解析后的 `accountId`、`strategyId`，即使 lots 为空也返回状态。
- 保留现有字段和空值语义。前端 DTO 集中定义；补齐 Trade 的四项费用及 revision，禁止页面自行定义互不一致的数据结构。

### 重算

- 沿用 `POST /securities/{id}/recalculate?accountId=&strategyId=`，保留 `rebuiltLots`、`rebuiltMatches`，可附加 `needsRefresh:false`。
- 将目标范围清标记放在现有重算事务内，重放完整成功后才执行；服务方法仍不自行提交。
- 既有“重新计算”入口也清同范围标记，不能只让新“刷新持仓”入口清标记。
- 客户端 `api.recalculate` 增加可选第三个策略参数；`api.lots` 增加可选策略参数，原调用保持兼容。

## 界面与请求生命周期

- 新增独立编辑弹窗，使用已有 Vue/Element Plus 风格；精确值用原始字符串预填，不复用展示格式器的三位价格或整数数量。
- 保存成功重新读取交易列表并提示“交易已保存，对应持仓需要刷新”；保存成功但列表读取失败须单独说明。
- 活动仓位增加范围行提示与“刷新持仓”；区域级待刷新清单覆盖无活动行/已结清个股，并标注账户汇总也可能尚未核算。
- 详情在批次区域展示持久状态，原重新计算与新刷新入口共享调用流程；明确重算范围、当前等量规则及止盈保留边界。
- 抽取共用前端重算调用/确认逻辑，不复制两套重算处理；以账户、证券、策略三元组管理在途操作。
- 首页使用 `dashboard.accountId` 和行 strategyId，不能读快速记账账户；跳详情添加账户/策略查询参数，详情校验其存在与归属后使用。裸路径仍沿用旧默认值，不新建策略管理界面。
- 确认前捕获三元组，确认后核对范围与页面代次；确认期间重复点击亦须防重。
- 写后失效旧批次/首页读取代次，再重新加载且不复用写前在途请求；沿用已有串行轮询和离页清理机制，旧响应不能把标记或数值写回。
- 不通过本地设置 `needsRefresh=false` 猜测最终状态。重算后恰有另一笔编辑时，以重新读取的真值继续显示待刷新。

## 状态与失败矩阵

| 事件 | 交易事实 | 派生数据 | 持久标记 | 界面 |
|---|---|---|---|---|
| 取消编辑或无变化 | 不变 | 不变 | 不变 | 关闭或提示无修改 |
| 非法输入/版本冲突/保存异常 | 回滚、不覆盖新版本 | 不变 | 不变 | 保留输入并给原因 |
| 实际编辑成功 | 新字段、版本、审计 | 仍为旧结果 | 真 | 提示待刷新 |
| 连续编辑多笔 | 各自原子保存 | 尚未重放 | 真 | 可一次统一刷新 |
| 行情刷新 | 不变 | 不重建账务 | 不变 | 行情状态独立 |
| 取消重算确认 | 不变 | 不变 | 不变 | 不发重算请求 |
| 重算失败 | 保留已提交编辑 | 删除/重建全部回滚 | 真 | 原因、继续更正与重试 |
| 重算成功 | 不因重算新增事实版本 | 按有效交易重建 | 仅本范围假 | 重读后更新 |
| 重算成功、后续 GET 失败 | 已成功提交 | 已成功提交 | 以服务端为准 | 提示页面读取失败，不报重算回滚 |

## 兼容风险与明确边界

- 延迟重算期间不保证读取的是一份完整旧快照：现金流可能已来自新 Trade，持仓/配对仍旧；最低价组、结清明细也可能混合新事实与旧投影。因此待刷新提示必须覆盖相关持仓与收益，不能继续宣称账务已核算。
- 时间/数量修改可能让历史暂时无法重放。允许保存合法单笔数据，再由显式刷新发现历史冲突，用户可连续更正多笔后重试，不在 PATCH 内隐式预演或重算。
- 待刷新期间原新增/卖出预览/撤销仍基于已有增量逻辑，可能依赖旧批次；提示待核算但不额外阻断交易，不清标记。若要改变此策略，须另行产品确认，不能实施时自行扩展。
- 现有重算逐字段恢复显式 ProfitTarget；价格/数量编辑后，旧参考价或计划量可能不适合新成本。沿用“复用现有重算”的边界，不擅自改用户止盈计划，提醒核对；个股/全局继承估价仍按现有读取计算。未持久化历史估价费率，不能声称无损自动重估。
- 需同步旧产品规格关于更正立即重算的描述，明确两事务流程和审计，保留数量/金额守恒等约束。

## 迁移与回退

- 在 0002 后新增 Alembic revision，仅创建状态表，不改写既有事实、配对、审计，不修改旧迁移。
- 临时文件库验证从 0002 升级后旧数据逐列不变、空状态按假读取；降级仅移除新增状态表。
- 本轮及自动验证不运行真实 `ledger.db` 迁移。部署时核对目标库与 Alembic 基线；先迁移再启动新版本，不能以 create_all 代替版本管理或自动 stamp。
- 数据编辑一旦启用，回退应用版本不会恢复旧事实，且旧版无法展示待刷新；回退前须保留审计与状态并处理全部待刷新范围，不能把删库作为回退方法。
