# 移动端高信息密度视图契约

## 1. 适用范围

适用于 `frontend/` 中除管理员页（`AdminUsersPage.vue`）外的全部业务页面与业务弹窗/抽屉。目标是在手机竖屏（`360px ~ 430px`）下实现纯上下滚动、零横向溢出和高信息密度展示，同时保持桌面端零破坏。

## 2. 签名与断点

- 视口判断统一使用 `src/utils/viewport.ts` 导出的 `useViewport()`，返回单例响应式 `{ isMobile }`。
- 断点固定为 `max-width: 768px`（与 `src/styles.css` 媒体查询一致）；桌面端（`>= 769px`）保留原有 `min-width` 与 Element Plus 侧边栏/表格结构。

## 3. 核心契约

- **共享业务逻辑，分端渲染视图**：移动端与桌面端共用同一 `<script setup>` 状态、轮询代次控制、并发锁、排序逻辑与接口调用，不得为移动端复制接口请求或重算账务。
- **零横向滚动**：`360px ~ 430px` 视口下所有业务页与弹窗均须满足 `document.documentElement.scrollWidth <= window.innerWidth`。
- **高信息密度与数字对齐**：
  - 移动端使用 `.m-*` 紧凑容器、1px 细分割线与等宽数字（`.num` / `tabular-nums`）；
  - 总览活动仓位采用全展开模式，每行常驻核心 3 列（证券/持仓、当前总价值+现价/涨幅、持仓浮盈/率）与底栏（最低价批次合计、待核算刷新按钮；不显示策略回本参考价），表头支持切换涨幅升降序且无行情持仓始终排末尾；
  - 移动端紧凑 `QuoteBadge` 中 `.quote-unit-price` 与 `.quote-change` 保持单行不折行（`white-space: nowrap`），实时行情隐藏「实时」标签，仅在行情「已过期 / 不可用」时展示状态标签；
  - 个股详情页常驻活动仓位切换列表：移动端吸顶横向滑动条（`.m-pos-strip`），桌面端左侧固定分栏（`.detail-pos-aside`）上下列表，按当前涨幅降序排列且无行情排末尾；移动端详情页操作栏（`.m-detail-actions`）与日内分时图（`.m-chart-box`）默认收起并支持一键展开。
- **弹窗与抽屉适配**：
  - 业务弹窗在移动端统一 `width="94vw"`、表单 `label-position="top"`；
  - `SellMatchDrawer` 在移动端使用 `size="100%"` 并以紧凑列表 `.m-match-list` 替代宽表展示配对预览。
- **桌面端零破坏**：桌面端模板分支保持原 DOM 结构与标题层级（`App.vue` 桌面端顶栏 `<h1>` 仅在 `/dashboard` 显示“总览”，其余页面显示“投资账本”，避免与页内 `<h2>` 触发 Playwright 严格模式冲突）。

## 4. 校验与状态矩阵

| 条件 | 界面行为 |
|---|---|
| 视口宽度 `<= 768px` | 渲染 `.m-topbar` + `.m-main` + 底部 `.m-tabbar` 及各页紧凑列表 |
| 视口宽度 `> 768px` | 渲染原有侧边栏、桌面顶栏与 `el-table`，DOM 结构不变 |
| 手机端点击“当前总价值”排序头 | 在当前涨幅降序与升序间切换，无行情持仓始终排末尾 |
| 手机端打开任意业务弹窗/抽屉 | 宽度不超出视口，表单顶置标签，无横向滚动条 |

## 5. 必须测试

- `frontend/e2e/mobile_layout.spec.ts` 使用 mocked API（禁止写入真实 `ledger.db`）覆盖 `390x844` 与 `360x780` 视口下的登录、总览排序、快速记账（买入与卖出预览确认）、个股详情（分时图/汇总/批次/已结清明细/止盈弹窗）、交易流水（含编辑弹窗）与复盘分析页，并断言零横向溢出。
- 运行 `pnpm run type-check`、`pnpm run build` 与全量 `pnpm run test:e2e`。
