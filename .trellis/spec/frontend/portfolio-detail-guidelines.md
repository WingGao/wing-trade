# 持仓详情与止盈交互契约

## 1. 适用范围

适用于 Dashboard 市值/证券查找、个股详情图表/批次、三级止盈和交易流水。沿用页面既有风格，账务计算归后端。

## 2. 签名

- `api.lookupSecurities`：外部候选可能没有本地 ID，选择时才创建本地证券。
- `api.intraday`、`api.lots`、`api.recalculate`、`api.profitSetting`、`api.saveProfitSetting`：以 src/api/client.ts 当前签名为准。
- `IntradayChart.vue` 显示真实时序，支持全绘图区指针吸附（二分查找最近横坐标点）、0% 基准线、右侧涨跌幅刻度与悬浮提示卡片；`LotTable.vue` 发出批次行 `setTarget`（设置止盈）与 `sell`（带入剩余数量打开卖出抽屉）事件。
- `App.vue` 顶栏全局账户切换器调用 `handleAccountChange(accountId)`，停留在 `/security/...` 时按涨幅降序跳转目标账户第一个活动持仓详情（无持仓回 `/dashboard`）。
- `formatQuantity` 整数展示，`formatMoney(..., digits)` 支持股价三位；`percentInputToRate`/`rateToPercentInput` 精确转换字符串。
- `utils/recalculate.ts` 的 `refreshPosition(scope, options)` 统一重算确认、防重、请求与失败分层；`isPositionRefreshing(scope)` 供两处入口绑定加载状态。
- `useLedgerStore().invalidateDashboard()` 使写前请求代次失效并停止复用旧在途读取；随后重新读取服务端快照。

## 3. 契约

- 止盈输入10%提交 `targetReturnPct:'0.1'`；后端浮盈返回10时直接显示10%。禁止将两种单位共用格式器。
- 首次加载和每3秒轮询串行读取 intraday，再读同价 lots。页面隐藏/卸载清计时器，切证券/账户推进代次，旧响应不能更新当前页面。
- 行情失败保留上一份真实参考并标记过期；批次浮盈只显示后端数值，已结清显示破折号；不能 Number 重算账务。
- 日内分时图与近期净值图支持整块图表区域悬停/点按吸附最近 X 轴数据点（无需精确指向折线点），展示十字准星、高亮点与悬浮提示（时间、价格/净值、相对 0% 基准的涨跌百分比，靠近边界自动防溢出）。0% 基准线优先取服务端 `quote.prevClose`（缺失或基金净值曲线时回退为首点价格），并将基准价纳入纵轴范围确保 0% 基准线恒可见；右侧展示对应涨跌幅刻度并在靠近 `0.00%` 时自动避让。
- 个股详情页在匹配同币种账户后同步全局活跃账户并按目标账户拉取活动仓位缓存，活动仓位列表仅展示与当前账户（加载前与当前币种）一致的快照。停留在个股详情页通过顶栏切换全局账户时，按活动仓位排序（涨幅降序、无有效行情置后）自动跳转到目标账户第一个持仓详情（携带 `accountId` 与 `strategyId`），无持仓时跳回 `/dashboard`，并以请求序号防止连续切换竞态。
- 个股详情使用 `LotsRead.summary` 展示总持股数、持仓成本、已实现收益和总浮盈；页面不自行相加、换算收益率或用格式化值回写。切换账户/证券或批次加载失败时清空汇总，异步响应继续按范围与代次校验。
- 总浮盈为 null 时显示破折号：仍有剩余持仓时提示“暂无有效行情”，无剩余持仓时提示“暂无持仓”；有参考值但行情过期时保留数值并提示“参考浮盈 · 行情已过期”。`includeClosed` 只控制批次和结清明细，不改变汇总。
- 个股按市场和代码同时识别，匹配币种账户；重算确认绑定发起时的个股和账户，确认后状态变化必须放弃旧操作。
- 股数展示整数，不改变接口原始数量字符串；当前价3位，持仓总价值与 valuationStatus 一致，部分覆盖不可显示部分总值。
- 批次按时间倒序，短 ID 悬浮全值；桌面端将数量与含费单价合并为「股数/份额 / 单位成本」、成本与现值合并为「成本 / 现值」、浮盈收益率与止盈目标合并为「浮盈 / 止盈目标」（一列多行，浮盈保留涨跌色），并在独立「操作」列（及移动端卡片头部）提供持有中批次的「卖出」与「设置」按钮。点击「卖出」通过 `SellMatchDrawer` 的 `initialQty` 以纯字符串规范化方式（去除小数末尾冗余零）预填该批次 `remainingQty`，顶部「卖出配对」入口打开时清空预填值；清空显式止盈目标恢复继承，不保存投影副本。
- 开启“显示已结清”时，批次表下的“已结清买卖明细”表默认展示 `closedTradeDetails` 全部行，不要求逐批展开，也不增加逐批请求。显示批次短ID、买卖方向、成交时间、原始成交价、本批数量、含费买入金额/卖出净回款和卖出已实现盈亏；原始整笔成交量辅助标注。卖出主数量及金额必须使用服务端本批分摊，不复制整笔成交。关闭开关隐藏，切证券/账户清理旧明细，异步响应复用现有代次防护。
- 卖出显式 EQUAL，确认携带预览中的明确 lotId/matchedQty，输入变化立即失效。
- trades 主显示代码和名称，内部 ID 仅辅助 title；排序时间倒序。
- 有效买卖流水可编辑时间、数量、价格、四项费用和备注；账户、证券、策略和方向只读。表单用原始字符串和时间精度预填，未变字段不经展示格式器重写；PATCH 带原 revision，仅提交变化字段。取消不写、失败保留输入；保存成功后的列表读取失败不能误报保存失败。长表单在常见桌面高度保留可见的保存/取消操作，表单体内部滚动。
- SQLite 回读后的既有 `executedAt` 可能是无时区 ISO 字符串，服务端约定其含义为 UTC。编辑表单在输入边界为这种原始值补 `Z`，预填和“是否修改”必须使用同一基准；仅改备注时不提交时间，不能经 `Date.toISOString()` 截断微秒。用户实际更改时间时仍须提供时区，不扩大本次兼容到其他展示格式器。
- 持久化 `needsRefresh` 来自服务端；活动仓位受影响行与个股详情显示待核算提示及“刷新持仓”。Dashboard 顶层 `pendingRefreshScopes` 为无活动行的历史个股提供入口，不受隐藏已结清影响；账户汇总也提示尚待核算。
- 重算范围必须同时捕获账户、证券、策略；首页使用 Dashboard 快照账户与行策略，跳详情保留范围。确认期间切换或离页则放弃旧操作，同范围从打开确认起即防重。
- 成功重算后失效写前 GET 并重读，不能本地无条件设 `needsRefresh=false`；新编辑可能已经再次置真。重算失败与成功后的页面读取失败分别反馈；行情刷新/轮询不得清除账务标记。
- 编辑数量或价格后提示核对显式止盈计划，复用已有保留语义，不在前端擅自重估目标价或计划量。

## 4. 校验与状态矩阵

| 条件 | 界面行为 |
|---|---|
| lookup 外部失败 | 显示失败信息，仍可选择本地候选 |
| 日内 points 为空 | 空态，禁止伪造折线 |
| 指针在股价图区域内移动 | 自动吸附最近横坐标点，显示十字准星与时间/价格/涨跌幅提示，3 秒刷新不丢失悬停位置 |
| 全天高开或低开偏离昨收 | 纵轴纳入基准价，0% 基准虚线与 `0.00%` 标签始终在绘图区内可见 |
| 停留在个股页切换顶栏账户 | 跳转到目标账户涨幅排序后的第一个活动持仓详情；目标账户无持仓时跳转 `/dashboard` |
| 请求期间切股/账户/离页 | 旧代次响应丢弃，不重新安排轮询 |
| 个股汇总请求失败或切换范围 | 立即清空旧汇总，迟到响应不能写入 |
| `summary.unrealizedPnl=null` 且仍有持仓 | 总浮盈显示破折号并提示暂无有效行情 |
| `summary.unrealizedPnl=null` 且无剩余持仓 | 总浮盈显示破折号并提示暂无持仓 |
| 汇总有值但行情过期 | 保留服务端参考值并显示过期说明 |
| 切换显示已结清 | 四项汇总值不变，只切换批次和明细 |
| 继承目标没有批次记录 | 显示来源和估计价，不发 createTarget |
| 止盈输入无效 | 显示错误，不提交浮点或NaN |
| 重算确认框期间换证券 | 不发送旧确认到新证券 |
| 开启显示已结清 | 自动显示全部原始买入与全部有效卖出，时间倒序 |
| 关闭开关或切换证券/账户 | 隐藏或更换对应明细，不能残留其他范围记录 |
| 编辑后取消、保存失败或版本冲突 | 不误报成功，取消不写，失败保留输入并说明原因 |
| 无活动批次但范围待刷新 | 活动仓位区域及详情仍可刷新 |
| 重算失败 | 保留服务端待刷新提示和原投影，允许更正后重试 |
| 重算成功、后续 GET 失败 | 说明重算已完成但页面读取失败，不声称重算回滚 |
| 写前 GET 晚于写后返回 | 丢弃旧响应，不覆盖新状态与数值 |
| 旧 executedAt 无时区且只修改备注 | 允许保存；按 UTC 提示原时间，PATCH 不含 executedAt |
| 重算后 GET 在途时切换已结清条件 | 丢弃旧条件响应并立即按最新条件读取，不取消 POST、不误报读取失败 |

## 5. 正常、边界与错误示例

- 正常：全局10%，某股20%，批次无覆盖，列表显示“继承个股20%”；清空个股后显示全局10%。
- 汇总：部分卖出后只显示剩余数量/成本与全部有效卖出收益，总浮盈直接显示后端值；开关结清前后四项一致。
- 边界：零浮盈显示0.00及0.00%，缺失显示破折号，两者不同。
- 错误：setInterval 叠加3秒请求；表单预填继承值并将其直接保存为覆盖。
- 编辑：原价格 `10.123456`、原数量 `1.2345` 保持原始精度；只改备注不把时间截为分钟或把费用清零。
- 刷新：同股不同账户/策略各有状态，刷新 A 范围不操作 B；快速记账账户不能充当当前看板账户。

## 8. 个股详情页 SSE 实时推送增量契约

- 进入/切换证券详情页后，通过 `quotesStore.watchSymbol('MARKET:CODE')` 登记临时订阅，离页或切换时自动释放。
- 通过 `projectLotsWithQuote(lots, holdingSummary, currentQuote)` 仅对 `status === 'OPEN'` 且有剩余数量的批次与总浮盈执行 `BigInt` 精确十进制实时派生，已结清批次与账务事实保持不变。
- 通过 `mergeQuoteIntoIntraday(intraday, liveQuote)` 对非 `nav` 曲线按分钟桶替换末点或追加新点（迟到旧包不倒退曲线）。
- 当 `quotesStore.isLive === true` 时关闭 3 秒 `intraday` 定时轮询并显示「实时推送」状态；SSE 不可用进入 `offline` 时平滑恢复 3 秒降级轮询。

## 9. 持仓批次按买入价格合并契约

### 9.1 适用范围

适用于个股详情（独立页与 PC 首页右栏内嵌详情）的「持仓批次」列表（`SecurityDetailPanel.vue`、`LotTable.vue`、`utils/lotMerge.ts`、`stores/preferences.ts`），以及后端 `GET /api/v1/securities/{id}/lots` 返回的 `purchasePrice` 字段。

### 9.2 签名

- `usePreferencesStore().mergeLotsByPrice`：布尔偏好，默认 `true`，持久化于 `localStorage` 键 `wing-trade:mergeLotsByPrice`；提供 `toggleMergeLotsByPrice()`。
- `buildLotDisplayRows(lots: Lot[], mergeByPrice: boolean): LotDisplayRow[]`、`resolveLotBuyPrice(lot: Lot): string`（位于 `frontend/src/utils/lotMerge.ts`）。
- `LotTable.vue`：新增可选 prop `mergeByPrice?: boolean`（默认 `true`）；`sell` 事件改为发出 `remainingQty: string`（兼容单批与合并组总剩余数量），`setTarget` 仍仅针对具体单条 `Lot` 发出。
- `SecurityDetailPanel.vue`：桌面端批次标题栏提供「按买入价合并」开关，移动端提供「按价合并」开关，透传 `:merge-by-price="preferences.mergeLotsByPrice"`。

### 9.3 契约

- **默认合并与分组键**：默认开启按买入价格合并；分组键为 `status + 规范化 6 位小数买入价`（优先使用后端返回的原始买入成交价 `lot.purchasePrice`，旧数据或缺失时回退 `lot.unitCost`）。`OPEN` 与 `CLOSED` 批次绝不混并。
- **精确聚合口径**：合并行使用 `BigInt` 精确十进制累加 `originalQty`、`originalCost`、`remainingQty`、`remainingCost` 与 `unrealizedPnl`（任一子批缺浮盈时合并行浮盈为 `null`），并按 `ROUND_HALF_UP` 计算加权含费均价（持有中用 `remainingCost / remainingQty`，已结清用 `originalCost / originalQty`）与合并收益率；严禁使用 JS `Number` 浮点累加。
- **单批无额外包装与排序**：分组内仅 1 笔批次时直接按原单批展示（`isMerged=false`，无合并标签与展开箭头）；组间及组内子批次均保持买入时间倒序（同时间按 `id` 倒序）。
- **交互与展开**：
  - 桌面端通过 `el-table` 树形行（`row-key="rowKey"`、`tree-props="{ children: 'children' }"`）展示合并组，点击「合并 N 批」标签、「明细」按钮或展开箭头可展开查看原始子批次并对其独立设置止盈或单独卖出。
  - 移动端在卡片头部展示「合并 N 批 ▾/▴」按钮，点击在卡片内展开/收起子批次列表，且保持 390px 视口零横向溢出。
  - 点击合并行「卖出」将合并组总剩余数量预填至 `SellMatchDrawer`；显式批次止盈仍绑定单条 `lotId`，合并行不伪造虚拟 `lotId`，当子批含显式止盈时提示「含 N 批独立设置（展开查看）」，无显式覆盖且上级来源与收益率一致时展示继承规则。

### 9.4 校验与状态矩阵

| 条件 | 界面行为 |
|---|---|
| 首次进入或未存储偏好 | `mergeLotsByPrice=true`，默认按买入价格合并 |
| 两笔 `OPEN` 批次买入价相同、手续费不同（`unitCost` 不同） | 按 `purchasePrice` 合并为 1 行，展示买入价与加权含费均价 |
| `OPEN` 与 `CLOSED` 批次买入价相同且开启「显示已结清」 | 按状态隔离，分别展示，不混并 |
| 某买入价仅有 1 笔批次 | 按原单批行展示，保留短 ID 与「卖出 / 设置」按钮 |
| 点击合并行「卖出」 | 卖出抽屉预填合并总 `remainingQty` |
| 点击合并行「明细」/ 展开按钮 | 展开原始子批次，每条子批次可单独「卖出」或「设置」止盈 |
| 关闭「按买入价合并」开关 | 恢复全部批次按时间倒序平铺展示，并持久化偏好 |

### 9.5 正常、边界与错误示例

- 正常：以 `10.000` 买入两笔（200 股含费均价 `10.025`、100 股含费均价 `10.050`），默认合并为 1 行（`合并 2 批`、剩 `300`、成本 `3,010.00`、买入价 `10.000`、含费均价 `10.033`）。
- 边界：同价多笔持有中批次均继承全局 `15%` 但因手续费差异导致各自目标估计价略不同时，合并行展示继承来源与 `15.00%`，不误显示其中某一批的目标估计价。
- 错误：直接按 `unitCost` 分组导致同价不同手续费的买入无法合并；或把 `OPEN` 与 `CLOSED` 批次合并导致数量和状态失真。
